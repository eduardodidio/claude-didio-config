# F33-T01 — DOB Config Schema

- **Wave**: 0
- **Type**: infra
- **Depends on**: (none)
- **Status**: planned

## User Story

As a framework maintainer, I want a `dob` config block in `didio.config.json`
so that benchmark behavior (K value, thresholds, paths) is centrally configured.

## Objective

Add the `dob` configuration block to `didio.config.json` and the template.

## Dev Notes

Edit `didio.config.json` (project root) and `templates/didio.config.json`.
Follow the existing pattern of other config blocks (e.g., `negotiation`,
`pipeline`, `token_monitor`). The config lib at `bin/didio-config-lib.sh`
uses `python3 -c` for JSON reads — no schema enforcement needed beyond
valid JSON.

Existing config: 207 lines. Add the new block after `blackhawk`.

## Implementation Details

**Files to create/edit:**
- `didio.config.json` — add `dob` block
- `templates/didio.config.json` — add `dob` block (defaults for new installs)

**Config shape:**

```json
"dob": {
  "enabled": false,
  "k": 3,
  "fixtures_dir": "tests/dob-fixtures",
  "results_dir": "logs/dob-results",
  "dimensions_schema": "docs/dob-dimensions.json",
  "regression": {
    "threshold_pct": 10,
    "block_on_regression": true
  }
}
```

## Acceptance Criteria

- [ ] `python3 -c "import json; c=json.load(open('didio.config.json')); print(c['dob']['k'])"` prints `3`
- [ ] `python3 -c "import json; c=json.load(open('templates/didio.config.json')); print(c['dob']['enabled'])"` prints `False`
- [ ] Both files are valid JSON (`python3 -m json.tool < didio.config.json`)
- [ ] No other config blocks modified

## Testing

- `python3 -m json.tool < didio.config.json` — validates JSON
- `python3 -m json.tool < templates/didio.config.json` — validates JSON
- Manual inspection of new block

## Test Scenarios

- Happy: config block present with all keys
- Edge: missing key falls back to default in consuming scripts (tested in T03)
- Error: malformed JSON caught by `json.tool`
