## Implementation Details

**F33-architecture.mmd** — Component/data-flow diagram showing:
- Fixture file (input)
- DOB Runner (orchestrates K runs)
- Per-run metrics collection
- DOB Scorer (aggregates results)
- DOB Regression Gate (compares baseline vs current)
- Config file (didio.config.json)
- Dimensions schema (dob-dimensions.json)
- Results storage (logs/dob-results/)

**F33-journey.mmd** — Operator journey (BPMN-style):
1. Operator prepares fixture
2. Runs `didio dob-run --fixture X --k 3`
3. Runner executes K iterations
4. Operator runs `didio dob-score <results-dir>`
5. Reviews summary.json
6. In CI: `didio dob-regression <baseline> <current>`
7. Gate decision: PASS/FAIL
8. If FAIL: investigate regressions, fix, re-run
