# Task F44-T07 — E2E Tests for Board Server & Rendering

**Feature:** F44
**Wave:** 2
**Type:** test
**Depends on:** F44-T01, F44-T03
**Status:** planned

## Objective

Create E2E tests that validate the board server starts, serves correct
data, and the HTML renders expected content.

## Dev Notes

- Test file: `tests/F44-board-e2e.sh`
- TAP protocol output
- Start server in background, run curl tests, kill server
- Use temp project dir with mock data for isolation

### Test Strategy
1. Create temp dir with mock warroom cards and pipeline states
2. Start `didio-board-server.py` with `DIDIO_PROJECT_ROOT=$TEMP`
3. Wait for server ready (curl retry loop, max 5s)
4. Test API endpoints via curl
5. Test HTML serves correctly
6. Kill server, cleanup

## Acceptance criteria

- [ ] AC1: Server starts and responds on configured port
- [ ] AC2: `GET /` returns HTML with correct content-type
- [ ] AC3: `GET /api/warroom` returns JSON with mock cards
- [ ] AC4: `GET /api/pipelines` returns JSON with mock pipelines
- [ ] AC5: API handles empty state (no files) gracefully
- [ ] AC6: API handles malformed JSON files gracefully
- [ ] AC7: Server shuts down cleanly
- [ ] AC8: TAP output with all tests numbered
- [ ] AC9: Cleanup trap removes temp files and kills server

## Test scenarios

- **Server start**: Python server starts on random port, GET / returns 200
- **Warroom API**: 3 mock cards → grouped by status correctly
- **Pipeline API**: 2 mock states → correct column derivation
- **Empty state**: No files → empty arrays, no error
- **Malformed JSON**: Bad file → skipped, rest returned
- **HTML content**: Board HTML contains expected board structure
